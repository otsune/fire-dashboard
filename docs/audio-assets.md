# 音源の準備

## 同梱チャイム

`chime_Eb5_C5_Eb5_Ab5.wav` は、Eb5 → C5 → Eb5 → Ab5（レ♯ → ド → レ♯ → ソ♯）の採用音源です。既存録音のサンプリングや第三者音源を使わず、2026-10-03に数式から独自合成しました。リポジトリの [Unlicense](../LICENSE) を適用します。

- PCM16、mono、48 kHz、3.2秒、307,244 bytes
- ピーク -12 dBFS、クリップなし
- SHA-256: `4486bbe635a74c647621f28c407e8b3067a523c11d0848110008961debcfab11`

通常の `npm run build` と `npm run dev` にはこのチャイムのみが入ります。「設定」→「時報の種類」→「チャイムのみ」を選び、時計に戻って「音声を有効にする」をタップすると試聴できます。ページを開く、設定を選ぶ、ビルドするだけでは鳴りません。

## 12時間用／24時間用の私用音声を取り込む

各形式の音声24本は公開リポジトリに含めません。手元にある私用ZIPを**リポジトリ外の私用フォルダー**へ展開します。元の `README-ja.md`、利用条件、provenanceはその場所に保管してください。音声本体とそのメタデータには本リポジトリのUnlicenseを適用しません。

既存の12時間用AyanaセットはElevenLabs Freeで生成した自宅・非商用向け音声です。公開GitHub、公開配布物、公開ホスティングへ含めないでください。後からの有料化で既存の生成物に商用ライセンスが自動付与されるわけではありません。利用範囲や帰属表示は音源付属の利用条件を確認してください。

12時間用（既存のAyana）と24時間用（Gemini TTS）は別の私用フォルダーに置きます。24時間用は「0時です」〜「23時です」で、午前／午後を付けません。生成元それぞれの利用条件を保管してください。リポジトリには生成済みの音声を置かず、未入手のセットを取り込んだことにはしません。

リポジトリのルートで実行します。各 `audio` ディレクトリには単一セットの `manifest.json` と、`hour-00` ～ `hour-23` のMP3またはWAVが必要です。GeminiのネイティブWAVもそのまま取り込み、MP3への再エンコードは行いません。manifestの `hours` は00〜23の各 `url`（例: `/audio/hour-00.wav`）と `license` を持ち、`chime` はnullで構いません。出力側のチャイムは既存のものを維持します。

```sh
npm ci
npm run build:private-audio -- --12h /path/to/ayana/audio --24h /path/to/gemini/audio
npm run preview
```

Windows PowerShellの例（自分の展開先に置き換えてください）：

```powershell
npm run build:private-audio -- --12h "C:\private\ayana\audio" --24h "C:\private\gemini\audio"
npm run preview
```

`--12h` または `--24h` の片方だけでもビルドできます。指定しなかった形式は未設定のままです。従来の引数1つだけの指定は12時間用として引き続き使えます。

このコマンドは指定した各セットの全24本・ファイル名・同一オリジンURL・権利情報・通常ファイルであることを確認してからビルドします。入力に欠損があれば以前のビルドを壊す前に停止します。音声ファイルのデコードや発音検査は行いません。

- 12時間用の出力：`apps/dashboard/dist/audio/private/hour-00.mp3` 等（元の拡張子を維持）
- 24時間用の出力：`apps/dashboard/dist/audio/private/24h/hour-00.wav` 等
- 出力の `/audio/manifest.json`：`hours` に12時間用、追加フィールド `hours24` に24時間用を登録。同梱チャイムと各音源のlicenseを維持
- 旧manifestの `hours` は12時間用として読み込み、24時間用へは流用しない
- 元ファイル、公開ソースのmanifest、設定の初期値：変更なし
- 私用README・provenance・生成履歴：配信ディレクトリへコピーしない
- 最後にService Workerを再生成し、音声とmanifestを版単位のオフライン資産に含める

`dist` はGit管理外ですが、**生成されたビルド全体が私用**になります。公開デプロイやGitHubのartifact添付には使わないでください。配備は既存の[運用と認証](deployment.md)に従う管理作業です。このコマンドはサーバー、Fire、認証・管理者設定を変更しません。静的な音声ファイルにも私用配信のアクセス制限が必要です。

通常の `npm run build` を再実行すると私用音声なしの配布物に戻ります。`npm run dev` とE2Eテストも公開ソースを使うため、私用音声の試聴には上記の私用ビルド後に `npm run preview` を使用してください。ZIPや読み上げMP3／WAVはGitへ追加せず、ignore設定を強制解除しないでください。

## 再生前の確認

私用ビルドをプレビュー、または承認済みの私用サーバーへ配置した後、「設定」→「時報の種類」→「チャイムと音声」を選びます。「12時間表記」がONなら12時間用、OFFなら24時間用の音声に自動で切り替わります。時刻表示と別の音声形式スイッチはありません。

初期表示は24時間です。12時間用しか取り込んでいない場合は「24時間表記の音声が未設定」と表示され、音声／両方モードは有効化できません。「12時間表記」をONにするか、24時間用を取り込んでください。チャイムのみはどちらの表示形式でも使えます。形式変更は再生中・待機中の音声を停止し、変更操作そのものでは鳴りません。未設定の形式へ切り替えると音声は無効になり、用意済みの形式へ戻しても再度タップが必要です。

時計に戻って「音声を有効にする」をタップすると、チャイム → 300 ms → 00時の音声で実際に再生を試します。「試聴」は10時の音声です。自動時報は設定タイムゾーンの00～23に対応し、静音時間と前面表示の条件を守ります。

更新済みの画面では「更新して再読み込み」で新しい資産一式に切り替えてから再度有効化してください。前のService Workerが動いたままだと旧manifestが使われます。私用音声を取り除いた場合も更新の切替を完了し、古いキャッシュが残らないことを確認してください。

実際のFireの前面ブラウザーで取り込んだ各セットの全24本を聞き、時刻・読み・音量を確認してから常設運用してください。特に4時・7時・9時・正午を確認します。12時間用の既存音声は深夜／正午に「午前0時／午後0時」と読みます（時計の12時間表示は12）。この音声は変更していません。次の表は12時間用音声セットの原稿であり、実機での発音を確認済みという意味ではありません。

## 時刻補正と再生権の安全性

ブラウザーのWeb Locksに対応している場合は、実際に生きているタブの排他権を持ってからIndexedDBの再生リースを確保します。時計が前進しても、別タブの再生中の権利を時刻だけで奪いません。対応ブラウザーではタブが終了するとWeb Lockが解放され、残ったリースも次の排他的な取得時に回復できます。

Web Locks未対応の場合は、安全のため他の所有者のリースを時刻だけで自動回収しません。タブの強制終了などで権利が残ると音声が停止したままになる場合があります。その場合はすべての同一ダッシュボード画面を閉じたことを人が確認してから、そのサイトの保存データを消去し、設定と音声の有効化をやり直してください。保存されたカードと時報履歴も消えます。実機の対応状況は未確認です。

保留中の時報も無効化、非表示、設定変更、時刻補正、10秒の期限超過で破棄します。音声を鳴らさなかった記録も再試行しません。
